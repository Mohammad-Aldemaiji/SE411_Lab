# Lab 15 – Spring CRUD with MySQL (Aiven)

This is the provided full CRUD solution (Courses API), moved from the in-memory H2 database to a MySQL server hosted on Aiven.

## Part B: what changed from H2 to MySQL

| File | H2 (before) | MySQL (now) |
|---|---|---|
| `schema.sql` | `id int GENERATED BY DEFAULT AS IDENTITY` | `DROP TABLE IF EXISTS course;` then `id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY` |
| `data.sql` | `values (default, ...)` | the `id` column is omitted and MySQL generates it |
| `pom.xml` | `com.h2database:h2` | `com.mysql:mysql-connector-j` (the current name of `mysql-connector-java`; Spring Boot manages the version). H2 is kept only for tests. |
| `application.properties` | nothing | MySQL datasource, `spring.sql.init.mode=always` |

The table is dropped and recreated on each start because MySQL keeps its data, unlike the in-memory H2.

I also fixed two small issues in the provided code:
- The `Location` header returned by `POST` pointed to `/api/v1/{id}`. It now points to `/api/v1/courses/{id}`.
- `deleteCourse` had an unused variable. It now uses `existsById`.

## Database credentials (not committed)

The Aiven connection details are not saved in the repository, because anyone who sees the repo could use them. `application.properties` reads them from environment variables:

| Variable | Value from the Aiven service page |
|---|---|
| `DB_HOST` | Host, e.g. `mysql-xxxx.h.aivencloud.com` |
| `DB_PORT` | Port, e.g. `21936` |
| `DB_NAME` | the database you created, e.g. `se411db` (this is also the default) |
| `DB_USER` | `avnadmin` (this is also the default) |
| `DB_PASSWORD` | your Aiven password |

- **Eclipse:** Run As → Maven build → goal `clean spring-boot:run`, then add the variables in the **Environment** tab.
- **PowerShell:** set each variable with `$env:DB_HOST="..."` (and the same for the others), then run `.\mvnw clean spring-boot:run`.

`mvn package` runs the tests against an in-memory H2 database in MySQL mode (`src/test/resources/application.properties`), so the build does not need the Aiven server.

## Part C: test the 5 CRUD operations (`http://localhost:3000/api/v1/courses`)

| Operation | Request | Expected |
|---|---|---|
| Read all | `GET /api/v1/courses` | 200, list of courses |
| Read one | `GET /api/v1/courses/1` | 200, or 404 if not found |
| Create | `POST /api/v1/courses` with body `{"code":"SE411","name":"Software Construction","description":"Labs","credits":3}` | 201 with a `Location` header |
| Update | `PUT /api/v1/courses/1` with the same body shape (no `id` in the body) | 204, or 404 if not found |
| Delete | `DELETE /api/v1/courses/1` | 204, or 404 if not found |

Invalid data, such as an empty `code`, a `name` shorter than 2 characters, or `credits` outside 1–10, returns 400.
